# Sai Lokesh Pusala

Cloud and data engineer focused on dependable data platforms, workflow automation, and practical observability.

I like building small tools that answer operational questions clearly:

- Did a schema change break a downstream pipeline?
- Which service caused a cost spike?
- Where did a batch workflow slow down?
- Can an ingestion event be replayed safely without duplicating work?

## Current Focus

- Python tooling for data quality, audit trails, and pipeline reliability
- AWS-oriented architecture patterns using Lambda, S3, Glue, Step Functions, and Airflow concepts
- Clean command line utilities with testable core logic
- Documentation that explains decisions, not just commands

## Selected Projects

| Project | What it demonstrates |
| --- | --- |
| schema-drift-sentinel | Detects schema changes across CSV or JSONL datasets and classifies impact |
| cloud-cost-anomaly-lab | Finds cloud spend spikes and explains service-level contribution |
| pipeline-pulse | Summarizes workflow health from structured pipeline events |
| event-replay-workbench | Simulates safe replay of object-storage ingestion events |

## Engineering Values

- Build the simplest useful version first, then make it observable.
- Prefer boring, readable code over clever code that nobody wants to maintain.
- Treat data pipelines as products: clear inputs, clear contracts, clear failure modes.
- Keep examples reproducible so someone can run the project without guessing.

## Tooling I Use

Python, SQL, AWS, Git, shell scripting, CI/CD concepts, Airflow-style orchestration, data lake patterns, and automation for repetitive operational work.
